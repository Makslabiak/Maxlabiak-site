# Dars Studio — дизайн-система

Редакция 2 (финальная, зафиксированная). Описывает ровно то, что лежит в `index.html` — absolute-канва 1440×800 с масштабированием через `transform: scale()`, компактная канва 1440×700 на планшете, полноэкранное бургер-меню.

Токены (переменные) — в `tokens.css`, подключай на каждой новой странице/секции.

**Важно:** была попытка пересобрать этот же экран на flow-вёрстке (flex, без absolute/scale) — рабочий вариант получился, но решили остановиться на текущей absolute-версии. Если понадобится вернуться к flow-варианту — придётся собирать заново, файлы той версии удалены.

## 1. Принцип адаптива — три режима, не один

Ключевое архитектурное решение, на которое опираются все остальные компоненты.

| Диапазон | Канва | Что происходит |
|---|---|---|
| **≥ 1200px** | 1440×800, hero 1400×760 | Десктоп. Фиксированная канва пропорционально масштабируется под ширину окна через `transform: scale()`. Координаты — абсолютные (`left/top` в пикселях канвы). Текстовое меню + пилюля «Связаться». |
| **720–1199px** | 1440×**700**, hero 1400×**660** | «Компакт». Та же техника масштабирования, но канва **меньше по высоте** — контент внутри неё подтянут вверх фиксированными px-значениями (см. раздел 5). Шапка: бургер + пилюля «Связаться» вместо текстового меню и nav-пилюли. Типографика заголовка/описания — та же, что на десктопе, не уменьшается. |
| **< 720px** | нет канвы | Отдельная мобильная вёрстка (`.mobile`). Никакого масштабирования — обычный flex-поток на реальных единицах (px/vw/clamp), плюс полноэкранное бургер-меню. |

**Почему у компакт-диапазона своя, уменьшенная канва, а не просто те же 800px:** при подтягивании контента вверх (чтобы строка статистики не уезжала за нижний край на невысоких окнах) под ним освобождается пустая зона — просто фото без текста. Решение — уменьшить саму карточку вслед за контентом, а не оставлять её прежней высоты с дыркой внизу.

**Почему не масштабируем чистым `scale()` до упора вместо трёх режимов:** ниже ~900px это убивает эргономику — тап-зоны становятся меньше 10px, текст расползается непропорционально экрану. Мобильный диапазон — заново собранная раскладка, а не уменьшенная копия десктопной.

**Технический нюанс канвы переменной высоты:** JS-скрипт масштабирования **не хардкодит** высоту канвы — он читает `frame.offsetHeight` в момент расчёта (это свойство не зависит от применённого `transform`, только от актуальной CSS-высоты). Если высота канвы для брейкпоинта меняется в CSS, скрипт подхватывает новое число сам:

```js
var s = document.documentElement.clientWidth / 1440; // BASE, ширина канвы не меняется
var H = frame.offsetHeight;                           // читаем актуальную высоту, не константу
frame.style.transform = 'scale(' + s + ')';
stage.style.height = (H * s) + 'px';
```

`html { overflow-y: scroll }` — обязательно, иначе появление/исчезновение вертикального скролла меняет `clientWidth` и картинка «прыгает» вбок.

**Практическое следствие для новых секций:** каждая следующая секция — либо (а) ещё один блок внутри той же техники масштабирования (для точности по Figma-макету), с параллельной мобильной flex-версией, либо (б) секция на относительных единицах (%, vw, clamp) без канвы.

## 2. Цвет

| Токен | Значение | Где |
|---|---|---|
| `--color-accent` | `#c9f24d` (лайм) | акцент в заголовке, hover-цвет ссылок и текстовых кнопок |
| `--color-white` | `#ffffff` | текст на тёмном фоне, фон primary-кнопки |
| `--color-black` | `#000000` | текст на белой кнопке |
| `--overlay-dark` | `rgba(0,0,0,.8)` | затемнение фоновой фотографии в hero |
| `--glass-bg` | `rgba(255,255,255,.2)` | фон обычных стеклянных пилюль на фото |
| `--glass-dark-bg` | `rgba(0,0,0,.35)` | фон полноэкранных панелей (бургер-меню) |
| `--glass-dark-border` | `rgba(255,255,255,.12)` | тонкая обводка тёмного стекла |

Правило: на фото — либо светлое стекло (обычные пилюли/кнопки), либо тёмное стекло (полноэкранные панели). Тёмное стекло — там, где панель перекрывает большую часть яркого фото и светлая версия будет слепить (сейчас только бургер-меню). Сплошных непрозрачных заливок на фото не используем.

## 3. Типографика

Два семейства, роли не смешиваются:

- **Manrope, вес 500** — заголовки, логотип, навигация, лейблы кнопок/пилюль
- **Inter, вес 400 (текст) / 900 (акцент внутри текста)** — описания, бейджи, статистика, primary-кнопка

| Роль | Десктоп/компакт (≥720) | Мобильный (<720) |
|---|---|---|
| Логотип | Manrope 500 25px/1, ls −0.5px | Manrope 500 20px/1, ls −0.4px |
| Nav / contact / ghost-label | Manrope 500 16px/1, ls −0.32px | Manrope 500 16px/1 |
| Compact-контакт (720–1199) | Manrope 500 18px/1, ls −0.37px | — |
| Бейдж | Inter 400 14px/1.3 | Inter 400 13px/1.3 |
| Заголовок H1 | Manrope 500 70px/70px, ls −1.4px | Manrope 500 clamp(35px,10vw,48px)/1.08 |
| Описание | Inter 400 18px/1.3 | Inter 400 16.5px/1.4 |
| Кнопка primary | Inter 400 18px/1.3 | Inter 400 16px/1 |
| Кнопка ghost | Manrope 500 16px/1 | Manrope 500 16px/1 |
| Статистика | Inter 400 18px/1.3 | Inter 400 14px/1.3 |
| Пункт бургер-меню (720–1199) | Manrope 500 44px/1.1, ls −0.02em | Manrope 500 clamp(28px,9vw,40px) |

Заголовок и описание в диапазоне 720–1199px **наследуют десктопные значения** — своей строки не имеют, отдельно не переопределяются.

**Типографская расстановка:** предлоги/союзы (из, и, в, на, с) склеены со следующим словом через `&nbsp;`: `из&nbsp;Директа и&nbsp;Авито в&nbsp;заявки на&nbsp;замер ... в&nbsp;Telegram`. Применять и в новых текстах.

## 5. Отступы, сетка и позиции контента по брейкпоинтам

- Канва десктопа: **1440×800**, карточка внутри — инсет **20px** со всех сторон (1400×760)
- Канва компакта (720–1199): **1440×700**, карточка **1400×660** (тот же инсет 20px)
- Горизонтальный отступ контента от края карточки: **70px**
- Мобильная карточка: margin **10px** от края экрана, паддинг контента **20px** по горизонтали, **24px** сверху

Вертикальные позиции контентного блока (`top`, в px от верха канвы):

| Элемент | Десктоп (канва 800) | Компакт (канва 700) |
|---|---|---|
| `.badge` | 181px | 140px |
| `.headline` | 218px | 172px |
| `.desc` | 449px | 400px |
| `.btn-primary` / `.btn-ghost` / `.pill--ghost` | 566px / 583px | 520px |
| `.stats` | 682px | 606px |

Фиксированные px, не проценты — с изменяемой высотой канвы проценты дают риск наложения блоков (заголовок в 2–3 строки занимает фиксированную высоту в px независимо от масштаба канвы).

**Единая высота кнопок:** `.btn-primary` и `.btn-ghost` выровнены через `display:flex; align-items:center; justify-content:center; height:52px`, не через `padding + line-height`. То же для мобильных — `height:48px`.

## 7. Компонент: бургер-меню

Работает одинаково в диапазоне 720–1199px (компакт) и <720px (мобильный), с отличиями в размере:

- **Кнопка-бургер** — круглая, светлое стекло, три линии; при открытии превращаются в крестик. 51×51px на компакте, 46×46px на мобильном.
- **Кнопка «Связаться»** рядом с бургером — светлая пилюля-стекло, +15% к обычной contact-пилюле: 51px на компакте (было 44px), 46px на мобильном (было 40px).
- **Панель меню — полноэкранная**, не выпадающий список: `position:absolute; inset:` в размер карточки (компакт — отступ 20px, мобильный — `inset:0`). Появляется **справа**: `translateX(100%)` → `translateX(0)`.
- **Фон панели — тёмное стекло** — на ярком фото светлое стекло слепит и спорит с фото.
- **Пункты меню — крупно, по центру**: `flex; align-items:center; justify-content:center`. 44px на компакте, `clamp(28px,9vw,40px)` на мобильном.
- **z-index**: лого и «Связаться»/бургер (`z-index:6`) всегда выше панели меню (`z-index:5`) — иначе бургер окажется под панелью и не закроет её.

## 8. Анимации

- Ховеры: `.2s ease`
- Открытие/закрытие панели меню: `.3s ease` на `opacity` + `transform`
- Иконка бургера: `.2s` на линиях

## 9. Чего не делаем (уже наступали на грабли)

- **Не масштабируем заголовок через `vw` без ограничения на десктопе** — `max(70px, 10vw)` без верхней границы раздул заголовок на широких экранах.
- **Не смешиваем светлое и тёмное стекло без причины** — тёмное только для полноэкранных панелей.
- **Не задаём высоту кнопок через `padding + line-height`** — только flex-центрирование.
- **Не используем `Math.max`/`Math.min` от ширины и высоты окна** для «идеального» масштабирования без обрезки/белых полей одновременно — математически невозможно гарантировать оба условия сразу; пробовали cover/contain/stretch, все давали артефакты. Рабочий вариант — масштаб только по ширине.
- **Проценты для вертикальных позиций контента внутри канвы переменной высоты — рискованны.** Только фиксированные px под каждый брейкпоинт.
- **Полная flow-пересборка (без absolute/scale) технически работала, но решили не переходить на неё** — если понадобится в будущем, это отдельная задача с нуля, не апгрейд текущей версии.
